# UXUI 상담 진단

프로덕트 디자이너 직무와 지원자 상담을 둘러싼 생각을 정리하고, 스쿼드에서 서로의 설명 방식을 맞춰보기 위한 컨설턴트용 자료입니다. **Vercel·DB·로그인 서버 없이 동작**합니다. 답안과 평가를 브라우저 안에서 처리하고 파일로 직접 전달합니다.

> 실제 이름·답안·채점 결과는 이 저장소에 올리지 마세요. 비공개 GitHub 저장소도 개인 평가 자료의 수집함이 아닙니다.

## 바로 사용하기: 설치 없이 HTML 열기

[offline](offline/) 폴더에 인터넷 없이 열리는 독립형 HTML 세 개가 있습니다. GitHub에서 파일을 선택한 뒤 **Download raw file**로 다운로드하세요. GitHub의 소스 미리보기는 실제 실행 화면이 아닙니다.

| 사용하는 사람 | 파일 | 하는 일 |
|---|---|---|
| 참여 매니저 | [시험지.html](offline/시험지.html) | 더블클릭 → 이름·5개 생각 작성 → 정리본 파일 다운로드 → 스쿼드에서 함께 이야기 |
| 채점 담당자 | [채점작업실.html](offline/채점작업실.html) | 더블클릭 → 받은 JSON 열기 → 점수·피드백 작성 → 결과 파일 내보내기 |
| 결과 수신자 | [결과확인.html](offline/결과확인.html) | 결과 JSON 파일을 열어 확인·인쇄 |

**가장 간단한 결과 공유:** 채점 작업실의 `결과 HTML`을 내려받아 해당 매니저에게 직접 전달하세요. 그 파일 하나만 브라우저에서 열면 자신의 답변·점수·피드백이 보입니다. 결과 확인 앱이나 인터넷 연결이 필요하지 않습니다. 브라우저의 인쇄 메뉴에서 PDF로 저장할 수도 있습니다.

HTML 파일은 먼저 기기에 내려받은 뒤 Chrome/Edge/Safari 같은 브라우저로 여세요. 메신저·메일의 첨부파일 미리보기는 JavaScript 실행이나 다운로드를 막을 수 있습니다. 시험 작성과 채점은 데스크톱 브라우저 사용을 권장합니다.

## 실제 운영 순서

1. 교육 담당자가 문항을 검수하고, 스쿼드에서 함께 이야기 나눌 목적과 시간을 안내합니다.
2. 매니저에게 **시험지.html만** 전달하고, 약 20분 동안 정답을 찾기보다 본인의 생각과 상담 경험을 정리해 달라고 안내합니다.
3. 매니저가 이름·5개 생각·참고 여부를 기록하고 JSON 또는 TXT 정리본을 내려받습니다. 파일은 스쿼드 논의 전에 준비합니다.
4. 각자 작성한 내용을 스쿼드에서 공유하면서, 직무 설명·지원자 기대 확인·과정 안내에서 서로 다른 지점을 찾습니다.
5. 스쿼드별로 반드시 전달할 내용과 먼저 확인할 질문을 정리하고, 첫 콜·첫 문자에 반영합니다.
6. 공용 PC에서는 응시 화면의 `이 브라우저 초안 초기화`를 사용하세요.

## 문항 구성

- 직무 설명: 초보자에게 프로덕트 디자이너 업무 설명
- 기대 확인과 상담: AI 이미지 제작을 기대한 지원자와 대화
- 문제 해결 과정: 가상의 쇼핑 앱 결제 이탈 사례
- AI 활용 이해: AI가 돕는 일과 사람이 판단·검증할 일
- 과정과 결과물: 포트폴리오와 구현 학습 범위

자료 근거: 사용자가 공유한 `[팀스파르타] UXUI 커리큘럼.pdf` 2–5쪽과 [KANT 과정 소개](https://kant.spartaclub.kr/ai-design). PDF 원본은 저장소에 포함하지 않습니다. 페이지·커리큘럼이 변경되면 문항과 기준을 검수하고 `ASSESSMENT_VERSION`을 변경하세요. 이전 문항 버전의 답안은 그 버전의 채점 작업실에서 처리합니다.

## 파일 형식

- `uxui-submission`: 이름, 문항 버전, 질문 원문, 답변, 참고 여부, 문서 ID 및 파일 생성 시각
- `uxui-grading-draft`: 답안 + 미완성 점수·피드백
- `uxui-result`: 답안 + 완성된 평가 + 결과 확정 시각
- 파일 크기 제한 1MB / 이름 80자 / 문항별 답변 6,000자 / 피드백 항목별 4,000자
- 초안 재다운로드 시 문서 ID를 유지합니다. 같은 문서 ID의 답변이 수정됐을 수 있으므로 파일 생성 시각과 내용도 확인하세요. 같은 ID의 브라우저 채점 초안 복원은 이전 답안까지 되돌릴 수 있어 명시적으로 선택하도록 되어 있습니다.

## 저장·개인정보·제약

- 앱 코드는 외부 API·폰트·분석 도구를 호출하지 않습니다. 답안과 결과를 서버에 자동 저장하거나 전달하지 않습니다.
- 임시저장은 이 기기의 브라우저 `localStorage`에만 남습니다. 다른 기기·브라우저와 동기화되지 않고 암호화되지 않습니다. 시크릿 모드·브라우저 데이터 삭제·저장 공간 제한으로 사라질 수 있으므로 **파일을 별도 보관**하세요.
- 응시 초안은 같은 브라우저의 임시저장으로 재개합니다. 답안 JSON을 응시 화면에 다시 불러오는 기능은 없습니다. 채점 초안은 JSON으로 재개할 수 있습니다.
- 정적 사이트에는 관리자 인증, 답안 무결성 서명, 비공개 해설 접근제어, 자동 수집, 공유 URL 저장소가 없습니다. 소스를 가진 사람은 문항과 평가 기준을 볼 수 있고, 답안·결과 파일도 수정할 수 있습니다. 보안 시험·공식 성적 증명 용도로 사용하지 마세요.
- 결과 공유는 개별 HTML/JSON **파일 전달**이며, 매니저별 서버 URL 발급이 아닙니다. 사람 이름이나 결과를 URL에 넣지 않습니다.
- 결과 파일을 GitHub, 공개 게시판, 공개 클라우드 폴더에 올리지 마세요. 담당자와 해당 매니저에게만 전달하고 보관 기간은 팀 정책에 맞춰 정하세요.
- GitHub Pages를 쓰더라도 **저장소가 비공개라는 이유만으로 웹사이트 접속이 제한되지는 않습니다.** Pages 접근 제한은 별도 상품·설정의 기능입니다. 무료 계정은 일반적으로 비공개 저장소의 Pages를 지원하지 않습니다.

## 개발 및 검증

실행 의존성·외부 빌드 패키지가 없습니다. Node.js 22 이상만으로 검사합니다.

```sh
npm test          # 파일 검증·점수·XSS 방지·다운로드 파일명·저장소 장애 테스트
npm run check     # JavaScript 문법 검사
npm run build     # site/ 소스로 독립형 offline/ HTML 재생성
npm run test:browser # 설치된 Chrome으로 오프라인 E2E (HTTP 서버 실행 없음)
```

`test:browser` 기본 Chrome 경로는 macOS입니다. 다른 환경에서는 `CHROME_PATH`로 실행 파일 경로를 지정하세요. 기존 브라우저 프로필을 읽지 않고 임시 프로필에서 검증합니다. 검증용 가상 답안·이미지는 시스템 임시 폴더에만 생성됩니다.

`site/`가 원본입니다. 소스를 수정한 뒤 `npm run build`를 실행하여 `offline/`도 갱신합니다. 최소 빌더는 이 프로젝트의 named import/export만 지원하며, 다른 모듈 문법은 명시적으로 실패합니다. `offline/시험지.html`에는 채점 루브릭 모듈을 포함하지 않습니다.

## GitHub Pages

2026-09-14 사용자의 명시적 승인에 따라 저장소를 **공개로 전환**하고, 무료 GitHub Pages 기본 주소를 사용하도록 설정했습니다. 기존 비공개 저장소는 현재 요금제에서 Pages를 지원하지 않아 공개 전환을 선택했습니다. Vercel·유료 도메인·별도 DB는 사용하지 않습니다.

- [매니저에게 전달할 시험지](https://jeonghunpyo.github.io/uxui-consultant-assessment/)
- [사용자용 채점 작업실](https://jeonghunpyo.github.io/uxui-consultant-assessment/grading.html)
- [결과 JSON 확인](https://jeonghunpyo.github.io/uxui-consultant-assessment/results.html)

링크로 응시해도 답안이 자동으로 수집되지는 않습니다. 답안 JSON을 내려받아 직접 전달하고, 개인별 결과는 HTML 파일로 공유합니다. 로그인·링크 접근제한은 없으며 문항·평가기준·소스가 공개됩니다. 실제 답안과 채점 결과를 저장소에 올리지 마세요.

`feat/static-assessment`의 `site/` 또는 Pages 워크플로가 변경되면 배포가 실행됩니다. `Actions → Publish GitHub Pages → Run workflow`로 수동 배포할 수도 있습니다. 저장소 변수 `PAGES_ENABLED=true`가 필요하며, 배포 대상은 `site/`의 응시·운영자 화면과 필요한 정적 모듈입니다. `offline/`, 테스트, 실제 답안·평가 파일은 Pages 배포 대상이 아닙니다. 응시 화면에는 운영자용 링크를 노출하지 않습니다.
